# LOM Bridge — mémo d'usage (lom.py, Remote Script UDP 7421)

- `python3 lom.py ping` → version + session ; les références `o:<session>:<n>` changent à chaque relance de Live.
- `python3 lom.py py "<expr>"` : expression Python dans Live (`song`, `app`). Pour un script : `scripts/pyl.sh fichier.py` (mettre le retour dans `result`, listes plutôt que dicts).
- `python3 lom.py param "<piste>" "<device|mixer>" "<param>"` → `ref nom min max valeur affichage …` (la ref sert à `read`).
- `python3 lom.py read "<piste>" <paramRef> <tA> <tB> <res>` : valeur réelle le long de la plage (transport ARRÊTÉ). `res` = points par temps : 0,25 = un par mesure, 1 = un par temps.
- `python3 lom.py apply spec.json [--dry]` : écrit l'automation d'arrangement. Attendre la fin : boucler sur `python3 lom.py jobs` tant que `running|queued`.
- Depuis 0.5.0, chaque écriture (`apply`, `shape`, `clear`) est **tout ou rien** (un clip qui échoue → tout est remis, message « étape annulée automatiquement ») puis **relue** : ligne `relecture: exact|sampled, n points, écart max …` dans le journal d'`apply`. `relecture: interrupted` = écrit mais non contrôlé → relire avec `read`. Un plan refusé pour « automation surchargée » = un paramètre automatisé a été bougé à la main : `python3 lom.py py "song.re_enable_automation()"` puis relancer.
- Depuis 0.6.0, commandes typées à préférer aux `/py` (aperçu, relecture, autorisées en HTTP) : `state --json` (carte du Set en début de séance), `transport [play <t>|stop|pos <t>|loop …]`, `meters <t> <secondes> [pistes]` (crêtes pendant la lecture, transport et curseur restaurés — remplace `levels.sh`), `setparam "<piste>" <device|mixer> <param> <valeur> [raw] [override]` (refusé si le paramètre est automatisé : passer par `apply`, ou `override` en connaissance de cause), `snapshot`/`restore <id>` (A/B et retour arrière en une étape), `locator <t> <nom>`/`locators`. Depuis 0.8.0 : `load "<piste>" "<nom>" [source] [replace=<device>]` (règle anti hot-swap appliquée et **vérifiée** : +1 device en fin de chaîne, rien d'écrasé, aucune autre piste touchée) et `notes get|set|add` (relecture note à note, défaite si Live n'a pas écrit ce qui était demandé). `/py` reste pour ce qui n'a pas de commande.
- Depuis 0.7.0 : les erreurs portent un code stable (`ERREUR [E_STALE]: …` → replanifier ; `E_ROLLED_BACK` → rien n'est modifié ; `E_ROLLBACK_FAILED` → faire Cmd+Z ; `E_AUTOMATED` → passer par `apply` ; `E_TRANSPORT_PLAYING` → arrêter la lecture). `lom.py journal [n]` relit les dernières écritures (à recopier dans la mémoire du morceau) ; `lom.py wait` remplace la boucle sur `jobs` ; `lom.py policy accept=expressions` évite de répéter l'accord sur chaque clip MIDI ; les temps `mesure|temps` suivent la signature du Set (`--bpb` pour forcer).
- `python3 lom.py ping` prévient si le bridge chargé dans Live n'a pas la version du script sur le disque (après un chargement de Set, le rechargement à chaud est perdu : relancer Live).

## Spec d'automation
```json
{"beatsPerBar":4,"automations":[
 {"track":"BUS - HARMONIE","device":"REQ 6 Stereo","param":"Band1 Frq","unit":"raw","res":8,"curve":"lin",
  "accept":["fades","warp","clamp"],"points":[["25|1",0.2565],["32|4.75",0.5615],["33|1",0.031]],"note":"…"}]}
```
- `device` : nom (unique sur la piste) ou `mixer` (`Volume`, `Pan`, `Send A`…). `unit` : `disp` (valeur affichée, résolue par dichotomie — échoue si l'affichage est arrondi, ex. Hz entiers de REQ 6 → utiliser `raw`), `raw` (0–1), `rel`.
- Une fenêtre = deux temps distincts ; un saut à la fin = deux points au même instant. `curve` `lin` sur un paramètre brut logarithmique (fréquences) donne une montée régulière en octaves ; `exp` reste longtemps bas.
- **Rien n'est automatisable hors d'un clip** : sur un bus/piste audio sans clip, poser un clip audio silencieux comme support (skill `live-automation`). Bus en Monitor In : le clip ne joue pas, l'automation reste.
- Les clips d'arrangement n'exposent pas leurs enveloppes ; le bridge reconstruit le clip (audio réimporté avec warp automatique → accepter `warp`). Après « Insérer Silence » de Live, clips, automations et repères se décalent ensemble (bonne méthode pour allonger une section : poser la boucle par `song.loop_start/loop_length`, vue Arrangement, Edition › Sélectionner boucle, Créer › Insérer Silence, relire).
- Charger un VST : `app.browser.plugins` → dossier `VST3` → chercher par `name` (récursif, profondeur 3) → `song.view.selected_track = t ; song.view.select_device(t.devices[-1]) ; app.browser.load_item(item)`. Presets Live natifs : `app.browser.sounds`.
- Vu-mètres : lire `output_meter_left/right` par appels séparés pendant la lecture (`start_playing()` puis `current_song_time = …`).
- **Agent sans accès UDP** (Qwen Code, Codex, autre terminal) : serveur `python3 lom.py serve --port 7480` lancé par l'utilisateur ou par Claude (jamais `--unsafe`), puis l'agent : `python3 agent_gateway.py inspect /state` → `preview spec.json` (plan serveur, rien n'écrit, deux empreintes) → `commit spec.json --sha256 … --plan-sha256 …` (replanifie ; refuse si la spec **ou** le Set a changé depuis le preview). Liste blanche lecture seule pour `inspect` ; jeton lu dans `connection.json`, jamais à recopier dans un prompt. Répétition hors Live : `tests/fake_live_server.py` puis `lom.py serve` (vérifié le 28 sept. 2026 ; pas encore dans Live).
- **8 oct. 2026 (Madame Gaspar)** : `lom.py load` d'un preset natif (« E-Piano MKI Mellow », « Kalimba Big ») → source **`sounds`** ; en `instruments` le parcours s'arrête au nœud d'appareil (Electric, Wavetable…) qui est chargeable et n'est pas un dossier, donc ses presets ne sont jamais trouvés. `setparam "<piste>" "Serum 2" …` vise le **rack** « Serum 2 APIintial » (macros seulement) et pas le Serum qu'il contient → régler par `/py` (chaîne 0, `PluginDevice`) en convertissant les affichages « 50% [-9.0 dB] » (prendre la valeur entre crochets), « 1.00 s » (×1000) et « -∞ ». `lom.py state` a renvoyé une sortie vide une fois sur un Set à 30 pistes (ping OK) → relire par `/py`.
- **Piège `meters` (8 oct. 2026)** : `lom.py meters 97 …` lit **97 comme un temps** (beat 97 = mesure 25), pas comme une mesure → écrire **`"97|1"`**. Et si le transport tourne, `meters` lit là où joue l'utilisateur sans déplacer le curseur : vérifier `transport` (0 = arrêté) avant de croire une mesure ; `transport stop` peut ne prendre effet qu'après l'appel suivant.

## Pièges vérifiés le 14 oct. 2026 (enregistrement, plug-ins maison)
- **Enregistrer à un endroit précis** : à l'arrêt, armer `record_mode` puis lancer la lecture fait repartir Live de son marqueur de départ (temps 0), même après `transport pos <t>` ou `transport play <t>`. Méthode fiable : `song.start_playing()`, puis `song.current_song_time=<t>` pendant la lecture, puis `song.record_mode=True` (punch-in). Arrêt : `record_mode=False` puis `stop_playing()`. Couper la boucle pendant la prise et la rétablir après.
- Une prise qui en recouvre une autre laisse de minuscules restes de clip en bordure : retenir le clip le plus long, filtré sur la position de départ.
- Live crée à l'avance le fichier de la prise suivante : l'horodatage du nom ne correspond pas au contenu (se fier à la date de modification).
- **Nouvelle version d'un plug-in** : rouvrir le Set ne la charge pas (le binaire déjà chargé reste en mémoire) ; il faut quitter Live. Si la liste des paramètres a changé, relancer aussi un scan, sinon Live garde l'ancienne liste.
- `Track.create_audio_clip(chemin, temps)` fonctionne (Live 12.4.6) ; le clip arrive warpé : `clip.warping=False` pour garder la vitesse d'origine.
- Les écritures LOM (`song.loop`, etc.) relues dans le même appel `py` peuvent encore montrer l'ancienne valeur : relire dans un appel suivant.
- Recaler un enregistrement sur le fichier source par corrélation : sur une musique répétitive, les pics à ±1 temps sont presque égaux ; limiter la recherche à ±20 ms autour de la position calculée.
- Le shell est **zsh** : `set -- $var` ne découpe pas les mots ; écrire les boucles à plusieurs valeurs en Python ou avec des tableaux.
